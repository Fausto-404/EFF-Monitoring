# EFF-Assistant 工单联动上线验收

适用版本：EFF-Monitoring v2.2.2 + EFF-Assistant v1.1.1。此清单用于上线前复验，不代表任意设备和网络环境都已得到验证。

## 部署顺序

1. 先更新 EFF-Monitoring API，确认 `/readyz` 返回正常，数据库中已自动创建 `plugin_alert_requests` 表。
2. 再更新 EFF-Assistant，在扩展管理页重新加载扩展，并刷新设备页面。不要只替换插件而保留旧后端；旧后端不能保证重试幂等。
3. 插件平台地址使用可同时访问前端和 `/api/` 的同一入口。Docker Compose 默认前端 `8080`，API `8000`；应填写前端地址。
4. 使用非只读账号新建 PAT，授予 `plugin:devices:read`、`plugin:parse`、`plugin:alert:create`。停用账号、吊销/过期 PAT 后应无法继续建单。
5. 安装插件时授予平台地址的站点权限；跨域 API 请求由扩展 service worker 发出，设备页面的 content script 不直接跨域请求。若浏览器拒绝站点权限，重新授权后再同步设备。

## 必须验收的场景

| 场景 | 预期 |
| --- | --- |
| 设备 URL 匹配、单条告警详情页 | 解析并生成一条工单，返回 Hash，工作台链接可打开对应告警 |
| 同一页面快速重复点击或超时后重试 | 返回同一工单，不新增重复记录 |
| 缺少建单权限的 PAT | 连接测试提示缺少 `plugin:alert:create`，旧配置显示无工单权限 |
| PAT 过期、吊销、创建人停用 | 建单失败并显示认证失效；不创建告警 |
| HTTP 设备页面 | 能生成请求标识并提交工单，无 `crypto.randomUUID` 依赖 |
| 设备页面文本超过 512 KiB | 提示打开单条告警，不向后端提交超大文本 |
| 平台暂时不可达、恢复 | 插件显示暂不可达；恢复并重新检查后可建单 |
| 与实际目标安全设备联调 | 核对字段解析、URL 规则、权限和页面 DOM；不得在生产真实封禁设备上做测试联动 |

## 自动化回归

- 后端：`docker run --rm --entrypoint python -v "$PWD:/app" -w /app -e PYTHONPATH=/app/backend:/app eff-monitoring-api:v2.2.2 -m unittest backend.tests.test_v222 -v`
- 插件源码目录：`node --test tests/ticket-contract.test.js`。
- 2026-10-27 本地测试：后端 7 项、插件 6 项回归通过；PostgreSQL 实例经真实 HTTP 创建并清理测试工单，8 个并发重复提交只生成 1 条告警；普通 HTTP 局域网地址下浏览器实测 `crypto.randomUUID` 不可用而 `crypto.getRandomValues` 可用。
- 上线前仍需在目标浏览器和实际设备页面做一次人工端到端验证，并观察 API 错误率与创建耗时；本地模拟测试不能替代此步。
